# safezone-packs

프리미어 프로 **SafeZone** 패널이 부팅할 때 받아가는 콘텐츠 팩.

이 저장소의 JSON 을 고치면 **팀원은 아무것도 안 해도** 다음에 패널을 열 때 반영된다.
플러그인 재설치(`.ccx`)가 필요 없는 유일한 축이다.

| 파일 | 무엇 | 쓰는 모듈 |
|---|---|---|
| `guide-spec.json` | 매체·게재면별 안전영역 좌표 (퍼센트) | M1 안전영역 가이드 |
| `seq-preset.json` | 규격 시퀀스 프리셋 | M2 규격 시퀀스 생성 |

패널이 읽는 주소는 `main` 브랜치의 raw 다:

```
https://raw.githubusercontent.com/enr-hash/safezone-packs/main/guide-spec.json
https://raw.githubusercontent.com/enr-hash/safezone-packs/main/seq-preset.json
```

---

## 고치는 법

1. 이 저장소의 JSON 을 고쳐서 `main` 에 푸시
2. 플러그인 폴더에서 검증 — **푸시 후 반드시**
   ```sh
   cd ~/Desktop/클로드/Plug-in
   node tools/check-remote.mjs
   ```
3. 패널 최하단이 `팩 <버전> · 동기화됨` 으로 바뀌는지 확인. 안 바뀌면 `[업데이트]` 를 누른다

`packVersion` 을 같이 올려라. 안 올리면 반영은 되지만 패널이 "이미 최신입니다" 라고 답해
바뀐 게 맞는지 화면에서 확인할 수단이 없어진다.

> **전파에 최대 5분** — raw.githubusercontent.com 이 기본 브랜치를 5분 캐시한다.
> 푸시 직후 `check-remote` 가 옛 버전을 보여주면 잘못 고친 게 아니라 CDN 이다.

## 좌표 규칙

- 전부 **퍼센트**. 그래야 1080×1920 이든 1200×1500 이든 같은 스펙이 정확히 맞는다
- `r: [x, y, w, h]` — 0~100. `x+w` · `y+h` 가 100 을 넘으면 플러그인이 팩 전체를 거부한다
- `t: "a"` = 피하라(위험영역) · `t: "p"` = 여기 놓아라(추천존)
- `l` = 라벨. 오버레이에는 글자가 안 들어가고(UXP 가 캔버스 픽셀을 못 읽는다) 패널 목록에만 뜬다
- **게재면마다 `a` 와 `p` 가 각각 하나 이상** 있어야 한다. 한쪽이 0개면 트랙이 비어 나온다

### `status` 를 함부로 `verified` 로 바꾸지 말 것

```
verified — 레퍼런스에서 실제로 재본 좌표
draft    — 형태만 맞춘 추정값. 패널에 주황 점으로 뜬다
```

지금 `verified` 는 `ig/reels` 하나뿐이다. 하이퍼그래피 레퍼런스 PNG(1081×1920)에서 실측했다.
나머지 12개는 추정값이다. 실측 없이 `verified` 로 바꾸면 편집자가 추정값을 사실로 믿는다 —
`status` 는 그걸 막기 위해서만 존재하는 필드다.

## 잘못 고쳐도 팀이 멈추지는 않는다

플러그인은 받아온 팩을 스키마로 검증하고, 실패하면 **내장 → 캐시** 순으로 물러난다.

```
내장(항상 있음) → 캐시(지난 성공) → 원격(최신)
```

깨진 JSON·범위 위반·모르는 `schemaVersion` 은 전부 거부되고, 실패한 응답이 캐시를 덮지도 않는다.
즉 최악의 경우 "안 바뀐다" 지 "안 열린다" 가 아니다. 그래도 `check-remote.mjs` 를 돌려라 —
조용히 안 바뀌는 게 제일 찾기 어렵다.

`schemaVersion` 은 **1** 이다. 플러그인이 이해하는 구조 버전이므로 손대지 않는다.
구조 자체를 바꿔야 하면 플러그인 쪽 코드가 먼저 나가야 한다(`.ccx` 재배포).

`latestPluginVersion` 은 팩이 실어 보내는 최신 플러그인 버전이다. 구버전 `.ccx` 를 계속 쓰는
팀원에게 알리는 신호이고, 새 `.ccx` 를 배포할 때 같이 올린다.
